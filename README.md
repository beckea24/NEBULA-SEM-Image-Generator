# NEBULA-SEM-Image-Generator
Generates SEM images using NEBULA Monte Carlo Simulator.

SEM IMAGE GENERATOR FROM STL Files

NOTE: Code is unfinished but does successfully output estimate images. Cannot be run on MacOS or Linux without changes (does work with WSL and WindowsOS).

Nebula SEM image generator utilizes NEBULA Monte Carlo Simulator to create realistic SEM images from an STL file.

This code requires installing NEBULA and CSTOOL from the NEBULA documentation (https://nebula-simulator.github.io/).

Code was written with assistance from Claude AI


## SECTION ONE -- USER INSTRUCTIONS

1. Install all required installations (listed at the bottom of this section)
2. Create materials (.mat) files using CSTOOL
3. Ensure all scripts and files are in the working folder
4. Run nebula_config.py 
5. Run individual scripts as needed

## SECTION TWO -- SCRIPTS

**nebula_config.py**
    
To run:
    
_python nebula_config.py_
    
This script runs all the steps from generating the .tri file to the SEM image, including the NEBULA simulation. It allows the user to import previously generate .tri, .pri, and .det files. If the user has a .det file, they do not need to import the .tri and .pri file. It assumes that the user has all of the .mat files listed already in their working folder, and does not currently allow new materials to be imported. If running NEBULA with a GPU, change "nebula_cmd" to the command below.

```
        nebula_cmd = [
            "nebula_gpu", 
            tri_file, 
            pri_file, 
            substrate_mat, 
            feature_mat
        ]
```

It is by default the CPU run.

```   
        nebula_cmd = [
            "nebula_cpu_mt", 
            tri_file, 
            pri_file, 
            substrate_mat, 
            feature_mat
        ]
```

**gds_to_stl.py**

To run: 

_python gds_to_stl.py_
    
This script is used to convert a GDS file to an STL file, which can be used for other purposes (like 3D printing a design). The user must edit the layer stack within the file to get the appropriate thicknesses for features. It is currently only defined for two layers.

**stl_convert.py**
    
To run:
    
_python stl_convert.py_
    
This script converts an STL file to a .tri file. It outputs the size of the STL feature in nm and requires the user to implement the substrate (unless it already exists in the STL, in which case you may enter 0s for the substrate floor). The feature width, length, and height are given for the user to make a reasonable decision on substrate size. The feature will automatically be centered on the substrate. 

**pri_gen.py**
    
To run:
    
_python pri_gen.py {desired file name}_
    
This script generates the .pri file with the name entered in the command line. This name will also be the name of the .det file generated by NEBULA, and the .png generated by the SEM generation script. 

**sem_gen.py**
    
To run:
    
_python sem_gen.py {output_file}.det_
    
This script creates the SEM image, and allows user to adjust contrast and brightness, and to save, or not save the image.

**triplot.py**
    
To run (does not need to be called):
    
_python triplot.py [filename].stl_
    
This script is a helper script for pri_gen. It creates a plot of the .tri file and allows the user to select the area to image.

**gds_to_tri.py**

To run:

_python gds_to_tri.py_
    
A script that allows users to create the .tri file without creating an intermediate STL file. Not used in nebula_config.py. Does not work for more than layer. Unknown if creates successful images.

**tri_view.m**
    
A MATLAB script that allows users to view their .tri file output in 3D. Generated by Claude AI.
    

## SECTION THREE -- FILE TYPES

--File types are described in NEBULA documentation as well

**.tri File**

The .tri file is the file that holds the shape information of features. It is created with triangles for each face, and each face is defined by the materials on the "outside" and "inside" of the face. (See NEBULA documentation for the definition of the direction of the face). When using NEBULA for SEM images, the features must have mirror walls from the floor of the feature to the ceiling of the detector. It must have a terminator plane a sitting below the bottom of the feature plane (10,000 nm underneath is used in stl_convert.py). It must have a substrate floor (defined by the user), which should be larger than the feature that is being imaged*. Finally, it must have a detector plane above the highest feature of the STL. 
    
It is best to limit the .tri file to be of only the desired feature, due to .pri file generation mechanics.

**.mat File**
    
The .mat file containing the material information. This is generated using CSTOOL. Follow instructions in the NEBULA documention to create the default .mat files, and look at the format to create your own.

**.pri File**
    
The .pri file contains the information of electrons over pixels. The beam height must be between the highest STL/.tri feature and the detector plane (a range of valid values are outputed in the stl_covert script). Following the user entering their desired magnification, a bounding box is displayed over a plot of the .tri file, allowing the user to select which area should be imaged**. The .pri file will generate information across the entire .tri file, not just the bounding box. It is best to limit the .tri file to be of only the desired feature.

The energy (called "Beam Energy" in terminal input) works the same as beam energy in an SEM. 
    
The electrons per pixel (epx) can be calculated to match real SEM parameters "electron current"/"aperture" and "dwell time" by the equation I*tdwell/qe (I =  electron current, tdwell = dwell time, qe = charge of an electron). This value greatly affects run time, and it has been found that 100 epx and greater can cause a crash when running the scripts on one CPU. 75 epx is good starting value, if matching an SEM's parameters is not possible. If the features start to blow out, lower the EPX. If they are very dark, raise the value.
    
Sigma is the standard deviation of Gaussian beam spot size. This affects the minimum resolution, where 0 is a perfect point beam (all electrons hit dead on). The default sigma is 1 nm.
    
Poisson shot noise is used for accuracy of simulation. It's default setting is True.\



_**Author Notes:**_

*Substrate floor thickness does not always behave as expected. Please enter the thickness of the real substrate of the file. It appears that the thickness of the substrate does not affect the image at all.

**Rotation of the bounding box is not yet implemented.
